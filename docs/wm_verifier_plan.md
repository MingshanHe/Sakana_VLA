# 计划：用 DreamerV3 世界模型给 action expert 的动作打分

日期：2026-11-09　|　前提：[report.md](report.md)（v0 结果）、[v1_plan.md](v1_plan.md)（基础改进）

你的想法：在训练 action expert 的同时训练一个 DreamerV3 世界模型，把 expert 输出的动作块送进世界模型"想象"一遍，用想象的结果判断哪个动作是最好的。这份文档回答三个问题：这个方向有没有研究前瞻性；别人做到哪了；我们该怎么做、先验证什么。

---

## 0. 一句话判断

**方向是对的、也是当前的热点，但"用世界模型挑动作"本身已经不是新点子了。** 要有研究价值，必须落在别人还没做好的三个点上，并且先做一个不需要训练的 go/no-go 实验（第 3 节）。

三个可能的创新点：

1. **潜空间世界模型，机载实时。** 现在的同类工作几乎都用像素/视频世界模型（1B 参数、秒级），只能用在机械臂上。RSSM 在潜空间里想象 16 个候选 × 12 步只要几毫秒，无人机 10 Hz 的 replan 也跟得上。
2. **世界模型同时当"记忆"和"裁判"。** RSSM 的循环状态天然是历史的压缩，正好补 v0 最大的短板（没有历史、分不清起点和终点）；同一个模型再用来给动作打分。一个模型解决两个问题。
3. **从"挑动作"走到"在想象里训练 expert"。** 这是 Dreamer 真正的用法：用世界模型的想象给 flow-matching expert 做强化学习微调，VLM 不动。目前这一步只有像素世界模型 + 离散动作 VLA 的版本（WMPO），潜空间 + flow expert 还没有人做。

## 1. 想法整理

```
                 N 份不同噪声                  想象 12 步（1.2 s）
  VLA (Qwen3.5 + expert) ──► N 个候选动作块 ──► DreamerV3 世界模型 ──► 每个候选的分数
                                                       │                   │
         当前 RGB-D、指令、状态 ──────────────────────┘                   ▼
                                                              执行分数最高的那个块的前 0.5 s，再来一轮
```

- **提案者**：现在的 flow-matching expert。它本来就是多解的（同一画面、不同噪声给出不同的转向），这正好是候选的来源。v0 的失败分析里"起点转向多解"就是一个现成的例子。
- **裁判**：DreamerV3 的世界模型（RSSM + 奖励头 + 碰撞头）。输入当前观测和候选动作块，想象之后 1.2 s 会发生什么，输出"会不会撞、会不会更接近目标、会不会看到目标"。
- **两个模型用同一份数据训练**，再加上 VLA 自己闭环飞出来的数据（这一点很关键，见第 5 节）。

## 2. 别人做到哪了

| 工作 | 做法 | 和我们的差别 |
|---|---|---|
| [V-GPS](https://arxiv.org/abs/2410.13816)（CoRL 2024） | 通用策略采样多个动作，离线 RL 训练的价值函数重排 | 价值函数不是世界模型，不想象未来；机械臂 |
| [RoboMonkey](https://mlanthology.org/corl/2025/kwok2025corl-robomonkey)（CoRL 2025） | VLA 采样 + 高斯扰动，VLM 做校验器挑最好的 | 校验器是 VLM，不是动力学模型；机械臂 |
| [RoVer](https://arxiv.org/pdf/2510.10975)（2025） | 机器人奖励模型做测试时校验器 | 同上 |
| [MG-Select](https://arxiv.org/html/2510.05681v1)（ICLR 2026） | 不用校验器，靠策略自己的置信度排序 | 是我们的一个必要对照：如果它和世界模型一样好，世界模型就没必要 |
| [Navigation World Models](https://arxiv.org/abs/2412.03572)（CVPR 2025 oral） | 1B 参数扩散视频模型，能给外部导航策略的提案排序 | **最接近**。但是像素级、秒级推理、地面机器人；没有和 VLA 联合训练 |
| [Test-time scaling for World Action Models](https://arxiv.org/abs/2607.17454)（2026） | 用预测未来帧的几何一致性给采样的轨迹排序 | 像素级；它也指出 N 大了以后会因为误判而变差，这是我们要防的 |
| [WMPO](https://arxiv.org/abs/2511.09515)（ICLR 2026） | 像素世界模型里做 on-policy GRPO 微调 VLA | 最接近第三个创新点；但是像素级、离散动作、机械臂 |
| [πRL](https://arxiv.org/abs/2510.25889) / [ReinFlow](https://arxiv.org/abs/2505.22094)（2025） | 给 flow-matching 策略做 RL 微调的技术（可算似然） | 是第三阶段的工具，不是竞争者 |
| 你自己的 Sakana_WAM `dreamer/policy.py` | DreamerV3 "shield"：64 个候选首动作，想象 10 步，按奖励 + 碰撞 + 价值挑最好 | **已经是这个想法的雏形**，差别是候选来自 Dreamer 自己的 actor，不是 VLA；只挑单步，不挑 chunk |

结论：**"世界模型给外部策略排序"有先例（NWM），"世界模型里 RL 微调 VLA"也有先例（WMPO）。** 没有人做的是：潜空间实时 + 无人机导航 + 世界模型兼做记忆 + flow expert 的想象微调。这些是我们要抓住的。

## 3. 先做 go/no-go 实验：oracle best-of-N（不用训练，一天）

Best-of-N 只在**候选里确实有好动作**时才有用。现在 v0 闭环 SR 是 0，候选里到底有没有好动作，不知道。所以第一步是用仿真的"上帝视角"来挑，测出这个方法的**上限**：

1. 每次 replan，让 expert 用 N 个不同的噪声采样 N 个候选块（N = 1, 4, 8, 16）。
2. 用仿真的特权信息给每个候选打分：沿候选飞 1.2 s 后到终点的最短路程是否变短（`GoalField.geodesic`）、是否会撞（`clearance`）、终点附近是否会看到目标。
3. 执行最好的那个。在同一个 64 条 unseen 集上评 SR。

判断标准：

- **oracle best-of-8 的 SR 明显上升**（比如 0% → 20% 以上）：说明 expert 已经会提好动作，只是不会挑。世界模型裁判有空间，继续本计划。
- **仍然接近 0**：问题在于 expert 根本提不出好动作。先做 [v1_plan.md](v1_plan.md) 的 P1–P3，再回来。但"世界模型当记忆"这一部分（第 4 节的 M）仍然值得做。

这个实验只改 `closed_loop.py`（候选采样 + 特权打分），顺便就得到了后面所有实验的上限曲线。

## 4. 技术方案

### 4.1 世界模型

直接复用 `~/sakana_dreamer/dreamer/dv3`（PyTorch DreamerV3，RSSM + 两热编码的奖励头 + 继续头，有 size12m–size400m 预设），改三处：

| 项 | 原来（Sakana_WAM） | 现在 |
|---|---|---|
| 图像 | 64×64 RGB-D | 先 64×64 RGB-D（数据集的 256² RGB + 深度缩小），有效再试 96² |
| 动作 | 4 维 [-1, 1] | 5 维 `[dx, dy, dz, dyaw, stop]`（和 expert 的每步输出一致，10 Hz） |
| 向量观测 | 速度、姿态、高度、航点 | expert 的 5 维状态（机体速度、转速、高度）；**不给航点**，因为部署时没有 |
| 数据 | 自己的 collect.py 回放 | 从 LeRobot parquet + 深度 npz 读；加 VLA 闭环飞出来的数据 |

预测头（都从潜状态出发，训练标签在数据里都有或者能离线算出来）：

- **碰撞 / 继续**：离表面 < 0.12 m 就算撞（和闭环评测一致）。
- **进度**：到终点的最短路程这一步减少了多少（离线用 `GoalField` 算，存成新的每帧标签）。
- **目标可见**：`observation.target_pixels` ≥ 150。
- （可选）**重建**：64×64 图像和深度，Dreamer 标配，也是开环检查的依据。

### 4.2 三个阶段

**阶段 A：安全 + 一致性裁判（不需要知道目标）**

分数 = −λ₁·P(撞) − λ₂·‖候选块 − 上一个块剩余部分‖ + λ₃·P(看到目标)。

- 不需要目标条件，所以最容易做对。
- 直接针对 v0 的两个失败：75% 碰撞、replan 之间左右摇摆。
- 验证：碰撞率下降；SR vs N 的曲线；和 MG-Select（置信度排序）、随机挑选对比。

**阶段 B：目标条件的价值**

- 加进度头：想象 12 步里到终点的最短路程减少了多少。
- 难点：世界模型本身不知道任务是什么。办法是把 VLA 的 prefix 特征（VLM 最后一层对指令 + 图像的池化，或 v1 里的目标框 token）作为条件输入进度头。训练标签是仿真里的特权信息。
- 这一步的本质是在学一个"导航价值函数"，在没见过的房子里会很难。所以只做"相对比较"（N 个候选哪个更好），不做绝对估计。

**阶段 C：在想象里训练 expert（研究核心）**

- 用世界模型想象 expert 的 rollouts，算优势（advantage），再用优势加权的 flow matching 或 πRL / ReinFlow 的方法更新 expert。VLM 冻结。
- 这是 Dreamer 的 actor-critic 换成 VLA expert，等于潜空间版的 WMPO。
- 风险最大、周期最长，放在 A、B 都有结果之后。

**贯穿三阶段的 M：世界模型当记忆**

- 把 RSSM 的 `deter` 状态（或者投影成 256 维）接到 expert 的状态 token 上。
- 这给 VLA 提供了历史，正好是 v1_plan 的 P1.2（历史帧）的替代方案，而且更便宜（不增加 VLM 的视觉 token）。
- 验证：和"进度状态"（P1.1）、"历史帧"（P1.2）三者对比起点误 stop 和 SR。

### 4.3 数据

- 现有数据集 1,723 条 / 26 万帧，字段齐全，直接可用。要新算一个"到终点的最短路程"每帧标签。
- **必须加 VLA 自己飞出来的数据。** 只用专家数据训练的世界模型没见过 VLA 的怪动作（原地打转、飞向墙），就无法正确判断它们。闭环每 32 条只要几分钟，一天能飞 1,000 条以上，撞墙的也要留着（这正是碰撞头需要的负样本）。
- 这和 v1_plan 的 DAgger（P4.2）用的是同一批 rollouts，一举两得。

### 4.4 计算量

- 世界模型 size50m–size200m。Sakana_WAM 里 size200m 在 H100 上 4.3 步/s（batch 16×64）；26 万帧 + on-policy 数据，2 万步约 1.5 小时。
- 推理：Sakana_WAM 的 shield 想象 64 个候选 × 10 步只用 16 ms。16 个候选 × 12 步完全在 10 Hz 预算内。
- expert 采样 N 个候选：VLM 的 prefix 只算一次，expert 5 步去噪 × N，开销很小。

## 5. 风险和对策

| 风险 | 说明 | 对策 |
|---|---|---|
| 候选里没有好动作 | best-of-N 救不了提不出好动作的策略 | 第 3 节的 oracle 实验先验证；不行就先做 v1 |
| 模型被"利用" | 挑分最高的，往往是世界模型算错的那个（2607.17454 也观察到 N 大了反而变差） | 多个世界模型的分歧当作不确定性惩罚；分数差距小时就用 expert 的默认输出；N 不要太大 |
| 不知道目标 | 世界模型只会动力学，不知道要去哪 | 阶段 A 先不依赖目标；阶段 B 用 VLA 的特征做条件，只做相对比较 |
| 分布偏移 | 专家数据里没有 VLA 的怪动作 | on-policy rollouts 必须进训练集（4.3 节） |
| 评测噪声 | 32 条太少 | 固定 64 条以上，报置信区间 |
| 撞车风险（研究上的） | 这个方向 2025–2026 很多人在做 | 把卖点放在潜空间实时、记忆 + 裁判合一、flow expert 想象微调；先把 SR vs N 的曲线做出来，快速写成一篇短文 |

## 6. 怎么证明它有用（评测设计）

1. **测试时扩展曲线**：SR 和碰撞率随 N（1, 4, 8, 16）的变化，三条线：oracle（上限）、世界模型裁判、MG-Select 置信度 / 随机挑选（下限）。这是最核心的一张图。
2. **裁判质量**：世界模型的排序和特权打分的排序的相关性（Spearman）、挑中最好候选的比例（precision@1）、1.2 s 碰撞预测的 AUC。
3. **消融**：只用安全项 / 加一致性 / 加目标价值；有没有 on-policy 数据。
4. **记忆对比**：VLA + RSSM 状态 vs VLA + 历史帧 vs VLA + 进度状态。
5. **阶段 C**：想象微调前后的 SR，和直接在仿真里 RL 微调对比（我们有仿真，可以衡量"想象"替代"真实交互"的效率）。

## 7. 顺序和时间

| 周 | 内容 | 产出 | 决策点 |
|---|---|---|---|
| 0 | oracle best-of-N（第 3 节） | SR vs N 上限曲线 | 上限 < 20%：先做 v1，本计划暂停 |
| 1–2 | 世界模型训练（数据集 + 1,000 条 on-policy）；阶段 A 裁判；开环检查 | 碰撞 AUC；SR vs N（裁判） | 裁判曲线贴近 oracle 的一半以上才继续 |
| 2–3 | M：RSSM 状态接入 expert，重训 stage A | 和 P1.1 / P1.2 的对比 | 选一种记忆方案进 v1 |
| 3–4 | 阶段 B：目标条件价值 | 消融结果 | |
| 5–8 | 阶段 C：想象微调 | 微调前后 SR | |

和 v1_plan 的关系：第 0 周和 v1 的 P0 可以并行；on-policy rollouts 和 v1 的 DAgger 共用；M 和 v1 的 P1.2 二选一。

## 8. 结论

- **值得做**，而且比"再加一个数据改进"更有研究味道。
- **但要以第 3 节的 oracle 实验为前提**。一天就能做完，能避免在一个没有上限的方向上花两个月。
- **卖点不要放在"世界模型挑动作"本身**，那个已经有 NWM 和一批测试时校验的论文了。放在：潜空间实时（无人机做得到，视频世界模型做不到）、记忆和裁判合一、flow expert 的想象微调。
- 手上的东西都是现成的：数据集字段齐全、闭环仿真几分钟一轮、Sakana_WAM 里有可以直接改的 DreamerV3 和 shield 代码。
